## DllBattle@0x76398 (0x3c), 0x71a2c (0x2c), 0x7198c (0x40), 0x73524 (0x40), 0x77338/0x77428 family

- 0x76398: bounded array push (`if (s->n >= 6) f394(0,0,0); s->a[s->n] = v; s->n++`, struct {u32 a[6]; u8 n}). Best 13/15 with `i = s->n; s->n = i+1; s->a[i] = v;` (also u8 i / `i = s->n++`). Only diff: retail `add r1,r0,#1; strb r1` , ours `add r2,r0,#1; strb r2` (register-allocation class; r1 is free in retail). Tried int/u8/unsigned i, store reorder.
- 0x71a2c (0x2c): `k=0x12c6; if (c->v != k) c->v = k; return f394b8(a, k, c) != 0;` (c = arg3, +0x6c) matches all 8 code words; the only diff is the literal pool: retail has a 0 pad word then the constant (function starts at 4 mod 8, pool 8-aligned), our standalone compile has no pad -> 10 vs 11 words. Not a masked match by the tool's rules; would be a match if the verifier tolerated pool alignment padding.
- 0x7198c / 0x73524: `&&` predicate chains (`p && f74420(p,13) && !(p->a&7) && !(p->b&7)`); armcc emits conditional execution (ldrbeq/tsteq/moveq) and narrows `&7` loads to `ldrb`, retail uses plain `ldr` + `bne`/`beq` branches. Known branch-vs-conditional-execution class; nested ifs/early returns/int fields did not change it (best 8/16, 4/16).
- 0x77338/0x77360/0x77398/0x773ec/0x77428 family (`f5dc68(this,*k)` then `f707d4(this->+8, r)` ...): retail does `mov r1,r0` then `ldr r0,[r4,#8]`; armcc emits `ldr r2,[r4,#8]` before the mov (scheduling class). Best 4/10 for 0x77338 with return-type/arg-type variants and local split. 0x77428 additionally starts with `mov r2,r1` (same pointer passed twice) that no simple form reproduced.
